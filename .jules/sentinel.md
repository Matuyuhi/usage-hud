## 2026-08-30 - [Untrusted Search Path (CWE-426) in ProcessSession]
**Vulnerability:** `ProcessSession` unconditionally prepends user-writable directories like `~/.local/bin` and `/usr/local/bin` to the `PATH` environment variable for all executed commands via `/usr/bin/env`. While this is necessary for non-standard tools like `gh` or `codex` installed via Homebrew, it creates a vulnerability when running standard system commands like `security` or `ps`. An attacker could drop a malicious executable named `security` in `~/.local/bin` and hijack the execution, potentially leading to command injection or privilege escalation.
**Learning:** Prepending custom search paths to resolve specific developer tools inadvertently compromises the secure resolution of standard system binaries.
**Prevention:** Introduce a mechanism (such as the `prependCustomPaths` parameter in `ProcessSession`) to conditionally modify the `PATH` so that standard system binaries like `security` and `ps` bypass the untrusted search paths and resolve securely.
## 2026-08-31 - [Untrusted Search Path (CWE-426) Bypass in ProcessSession]
**Vulnerability:** Even when `prependCustomPaths: false` is used in `ProcessSession`, the system's `PATH` from the environment is still used to resolve commands. If the app is launched from an environment where `PATH` already contains user-writable directories (like `/opt/homebrew/bin`), `env` will still resolve system binaries from those untrusted directories, resulting in a CWE-426 Command Injection vulnerability.
**Learning:** Relying on the user's base `PATH` environment variable for system binaries is insecure if the environment is already tainted.
**Prevention:** Explicitly set `PATH` to standard system directories (e.g., `/usr/bin:/bin:/usr/sbin:/sbin`) when invoking system binaries to completely bypass the untrusted environment variable.
## 2026-08-31 - [Unbounded Buffering (CWE-400) in ProcessSession]
**Vulnerability:** `ProcessSession.readUntilEOF()` and `ProcessSession.waitForLine()` read process stdout into memory unconditionally until EOF or a timeout. A malicious or malfunctioning child process could output an enormous amount of data, causing unbounded memory consumption and leading to an Out-of-Memory (OOM) crash in the parent application (local DoS).
**Learning:** Any operation that buffers input from an external process or network socket must enforce a maximum size limit, even if the external entity is a trusted local utility, to prevent accidental or intentional resource exhaustion.
**Prevention:** Implement a maximum buffer size limit (e.g., 5MB) in all stream-reading loops. If the limit is exceeded, cleanly terminate the read operation (truncate) or throw a descriptive error.
## 2026-08-31 - [CWE-426 Command Injection via /usr/bin/env]
**Vulnerability:** Invoking processes using `/usr/bin/env <command>` introduces a subtle command injection vulnerability even if the `PATH` environment variable is sanitized. Relative commands can resolve against the current working directory, and the wrapper obfuscates explicit secure execution.
**Learning:** Depending on wrappers like `env` means relying on their internal resolution mechanics which may differ from expected safe path resolution, particularly on arbitrary systems or misconfigured environments.
**Prevention:** Always manually resolve absolute executable paths (e.g., via `FileManager.default.isExecutableFile(atPath:)`) and assign the exact absolute path to `process.executableURL`. Only use `env` when specifically needing dynamic resolution without tight security constraints.
